# 知行小课｜部署声明与验收边界

本文描述仓库当前能够支持的最小容器化运行方式。它不是某个云平台的配置，也不代表已经完成公网部署、真实模型端到端验收或赛事官方提交。

## 运行方式

项目使用 Node.js 24、原生 HTTP/fetch 和 ES modules，没有生产依赖安装步骤。`Dockerfile` 使用 Node 24 Debian slim 的 builder/runtime 两阶段构建：builder 复制 `package.json`、`src/` 和 `public/`，逐个执行 `node --check` 并检查 `public/index.html`；runtime 只复制这些运行文件，以官方 `node` 用户（非 root）启动 `node src/server.mjs`，默认监听 `0.0.0.0:3000`。镜像健康检查访问 `GET /api/health`，仅表示进程存活，不表示模型额度、知乎接口或公网链路已就绪。

```powershell
docker build --tag zhixing-learning-workbench:local .
docker run --rm -p 3000:3000 --env-file .env zhixing-learning-workbench:local
```

**2026-09-13 更新：daemon 已运行，构建与容器检查已实际完成。**`docker build` 成功，三个容器（demo / live / demo-server）均达到 `Up (healthy)`，`/api/health` 与首页返回 200，live 模式下 `/api/knowledge` 取得真实赛事列表。镜像内已核实不含 `.env`、`*.key`、`*.pem`，容器环境变量无 key/secret/token。详见 [容器验收-2026-09-13](容器验收-2026-09-13.md)。

`.env` 只应存在于部署主机或 secret manager，不应提交；不要把真实值改写进 Dockerfile、镜像层、前端代码、日志或验收记录。`.dockerignore` 排除 `.env`、`.local/`、`sources/`、测试、文档、vendor 和本地依赖；镜像内不包含密钥、官方内容样本或本机凭证。

## 必填生产配置

- `MODEL_BASE_URL`、`MODEL_NAME`、`MODEL_REASONING_EFFORT`：按赛事供应商实际可用配置填写。
- `MODEL_API_KEY` 或 `ZHIHU_OPENAI_NEXT_API_KEY`：只注入部署平台 Secret，不写入镜像、Git、前端或日志。
- `ZHIHU_CONTENT_MODE=live`：正式体验必须使用赛事内容；`demo` 只能作为明确标注的离线演示。
- `HOST=0.0.0.0`、平台提供的 `PORT`。
- `ALLOWED_ORIGIN`：填写唯一 HTTPS 公网来源；保持 `REQUIRE_ORIGIN=true`。
- 真实登录会话或受信任网关凭证：设置 `GENERATION_SESSION_COOKIE_*`、`GENERATION_GATEWAY_TOKEN` 或 API 客户端 Bearer，不能把静态令牌放进 `public/app.js`。
- 根据实际模型计费设置 `MAX_GENERATION_PER_WINDOW`、`MAX_GENERATION_REQUESTS`；当前闸门是单实例请求次数，不是 token/金额计费系统。多副本部署还需外部网关或共享限额。

7. 记录公网 URL、部署时间、平台版本、配置摘要（不含 Secret）和验收结果；再进入赛事提交页。
