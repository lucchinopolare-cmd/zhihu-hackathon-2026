## 1. 调研范围与证据边界

本轮先对照本项目的 [产品需求文档](产品需求文档.md)，再通过浏览器查看公开 GitHub 项目主页与 README，重点寻找“带来源的讲解、主动学习、个性化行动、多内容对照、学习进度和多模态”相关功能。

- 没有下载、复制或改写第三方代码、提示词、界面文案和素材。
- 下表中的“已有功能”是项目维护者在公开 README 中的描述；本轮没有部署或运行这些第三方项目，不能把它们当作独立验收结论。
- GitHub 星标、版本和 README 会变化，因此本文不把即时数字作为产品判断依据。
- 开源许可允许某些复用，不等于满足本次赛事的独立原创要求。本项目只借鉴问题拆解和交互思路；若以后确需使用依赖或片段，必须另行核对固定版本、许可证、归属和赛事规则。

## 3. 针对当前作品的功能优先级

当前首版已经有：直接 AI / 自行复述双入口、逐字引用与原文定位、深度讲解、继续追问、行动编辑和 Word 学习卡导出。因此不建议再堆普通摘要、通用聊天或另一套卡片导出。

| 优先级 | 候选功能 | 用户流程 | 价值 | 预计改动 | 主要风险 |
|---|---|---|---|---|---|
| P0 | **证据分层** | 页面只用“原文理解”和“AI 延伸”两类标签；原文类陈述可点回逐字引文，AI 类陈述明确是解释、场景或建议 | 把现有引用从“引文存在”提升为“用户能判断作者内容与应用延伸”；与知乎内容和可信学习高度贴合 | 小—中 | 标签不是自动事实核查；没有可靠依据的陈述不写成原文理解 |
| P0 | **一分钟理解挑战** | 讲解后出现 1 个短问题；用户先答，再显示核对、原文依据；若遗漏关键条件，只追加 1 个变式题 | 把被动阅读变成检索练习；比一次生成十张闪卡更聚焦，也能复用现有复述核对与引用校验 | 中 | 不做未经验证的分数，不宣称“已经掌握”；题目必须能被当前片段支持 |
| P0 | **公网生成保护** | 相同文章和生成方式优先复用短期缓存；重复点击合并；显示真实等待/失败状态；设置累计预算或访问限制 | 不是展示噱头，但直接决定评委能否稳定体验，也可降低赛事额度风险 | 中 | 不能用虚假的阶段进度掩盖一次长请求；缓存要区分模型/提示版本 |
| P1 | **把建议换成我的场景** | 结果后提供可选的一句话输入“我想把它用在……”；AI 只重写行动、完成标志和回顾安排，并保留“AI 延伸”和“待尝试”标签 | 直击“看懂了但不会用”；比让用户手动改整段行动更自然 | 中 | 不假设用户已承诺执行；敏感或健康场景要保持边界 |
| P1 | **双文观点对照** | 用户再选一篇知乎内容；输出共识、分歧、各自适用场景，每项分别绑定两边引文 | 很贴合知乎多元观点和“知识再生产”，创新度可能高于通用学习助手 | 中—大 | 两篇材料会增加延迟和 token；标签样本不可靠，应由用户选第二篇或谨慎推荐 |
| P2 | **本机复习架** | 不登录，使用浏览器本地存储保存看过的文章、自己的回答、行动草稿和自选回顾日期 | 增加回访价值，保护隐私；可在无 OAuth 时成立 | 小—中 | 只能叫“复习记录”，不能把浏览/导出推断为学习完成或现实行动完成 |
| 暂缓 | 朗读、多语言、播客、PDF 上传、知识图谱、多模型切换、长期学习仪表盘 | — | 都在同类项目中常见，但不是当前核心问题的最短路径 | 大—很大 | 稀释知乎结合点、增加依赖和验收面，48 小时内容易损害完成度 |

## 4. 建议的最小组合

如果只增加两项，建议选择：

1. **证据分层**：让评委一眼看到本项目不是普通总结器，而是在帮助用户核对“作者说了什么、AI 又加了什么”。
2. **一分钟理解挑战**：让用户产生一次真实输入，再用原文反馈；遗漏条件时才生成一个变式题。

如果真实模型和公网体验已经稳定，再增加“把建议换成我的场景”。“双文观点对照”可作为展示型加分项，但只在单文流程稳定、延迟可接受时实现。

一个适合 3 分钟 Demo 的连续流程是：

```text
选一篇知乎内容
  → AI 拆解观点，并把陈述标成“原文理解 / AI 延伸”
  → 用户回答 1 个理解问题
  → 系统用原文指出遗漏条件，并给 1 个变式题
  → 用户输入自己的使用场景
  → 得到可修改、仍标为“待尝试”的小行动
  → 导出带来源的学习卡
```

## 5. 防止“借鉴变抄袭”的执行线

- 借鉴的是“为什么需要这个功能”和“用户完成什么动作”，不照搬页面布局、命名、提示词、数据结构、代码、截图或宣传语。
- 每项新功能先写成自己的验收标准，再从现有架构独立实现；保留设计草稿、AI 对话、测试和提交历史。
- 文案继续围绕本项目自己的区分：知乎原文、作者观点、AI 解释、用户文字、待尝试行动。
- 不从 NoteBotLM 复制任何代码或素材；其 README 显示许可证限制比常见开源许可证更严格。
- 即使是 MIT/Apache-2.0 项目，也不能把大段代码改名后当作赛事原创；若确需引入成熟库，只使用公开发布的通用依赖方式，并保留许可证与归属。
- 在计划书中可以列出公开竞品与差异，但不要声称别人没有某项功能，除非另有充分、可重复的产品核验。
