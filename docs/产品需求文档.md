# 知乎知识学习助手｜产品需求文档 v0.1

日期：2026-09-11。工作名称暂用“知行小课”，最终命名、技术栈和团队分工待确认。

本文是产品实现依据。赛事规则与当前验证状态见 [项目档案](../项目档案.md)，不能将本文的设计要求视为已经实现。

## 1. 已确认需求与设计假设

**用户已确认：允许跳过自己复述，直接使用 AI。**不愿意先输入的用户，也应当能够获得有用结果；本轮要求先形成需求文档，再查找和下载适合项目的 skill。

当前工作方案：将知乎知识内容转为可核对的讲解和一个可尝试的行动。目标用户暂定为想改善学习方法的大学生，痛点假设是“看过建议，但不知道具体怎么用”。这些仍需真实试用验证，不代表已经证明学习效果。

此前“所有人必须复述”“必须修订或确认理解才能生成行动卡”的设计建议不作为本版门槛。用户可直接使用 AI、查看结果并导出；来源及 AI 生成标识必须保留。

## 2. 产品价值与首版目标

让用户从一篇知乎知识内容出发，获得三样东西：

1. 容易理解的核心观点、作者公开写出的论证步骤与适用条件。
2. 可以回到当前原文片段核对的依据，以及 AI 标明的边界和反例提醒。
3. 一分钟理解挑战、具体应用场景、值得继续追问的问题，以及一个有完成标志、可以按个人场景调整的小行动建议。

希望深入思考的用户可以自行复述；希望省事的用户可以直接让 AI 讲解。两种方式均不把赞同作者当作理解正确，不把生成建议当作已经学会或已经行动。

## 3. 核心用户流程

### 路径 A：直接用 AI（推荐入口）

选择内容 → 点击“AI 帮我读懂” → 查看带引用的讲解 → 可选继续追问 → 查看并修改行动建议 → 导出学习卡。

- 生成前无需填写复述、问卷或行动表单。
- AI 输出包含核心观点、作者的公开论证步骤、适用条件、批判性提醒、具体场景、后续问题和一个行动草稿。
- 每条依赖原文的主要观点提供可核对的引用；追问回答按陈述逐条绑定引用。行动草稿若是应用情境的延伸，应明确为“AI 建议”，不能归为作者原话。
- 用户可以直接查看和导出，也可以修改。页面不强制要求再次确认“已读懂”。
- 没有用户修改时，导出内容标注“AI 讲解 / AI 行动建议”，不能出现“我的复述”“我已掌握”等不真实标签。

### 路径 B：自己复述

选择内容 → 点击“我先说说理解” → 输入自己的复述 → AI 带引用核对 → 可选修订 → 查看行动建议并导出。

- 输入提示：“作者建议什么？在什么情况下适用？”允许用户表示存疑或不同意。
- 反馈区分复述准确处、遗漏条件、超出当前片段支持的推断；无依据时说明无法判断。
- 保留最初复述与用户修订后的文本，不能由 AI 悄悄覆盖用户原话。
- 用户随时可以切到直接用 AI；已输入文本在当前页面内保留。
- 不设置未经验证的理解分数或“通过考试”结果。

### 两条路径共有的规则

- 阅读、生成、修改和导出在一个连续工作台完成。
- 切换文章时先处理未保存输入，防止将上一文章的引用、反馈或行动带入新文章。
- 卡片记录内容作者、标题、来源标识、引用片段、生成方式、用户编辑情况和生成时间。
- 行动默认状态为“待尝试”；导出不代表执行成功。首版不验证现实行动是否完成。
- 页面证据标签只保留“原文理解”和“AI 延伸”。核心观点、论证步骤、适用条件属于带逐字依据的原文理解；批判性提醒、构造场景和行动建议属于 AI 延伸。没有可靠依据的内容不作为原文理解展示，不另设“证据不足”标签。
- 讲解后给出一个能由当前片段核对的一分钟理解问题。用户回答后只反馈关键点是否覆盖，不给分、不宣称掌握；仅在有关键遗漏时追加一个变式题。
- 用户可输入自己的使用场景，让 AI 先提取具体学科/任务、时间、目标产出或卡点，再重写行动、完成标志和回顾安排；三者都必须因场景而改变，结果仍标为“AI 延伸”和“待尝试”。

## 4. 页面与交互设计

### 内容入口

展示官方知识列表中实际存在的标题与摘要，允许在已加载列表内筛选。优先推荐适合首版场景的内容，但不把原始标签直接当作可靠学科分类。

选中文章后展示作者、标题和可读内容范围。空列表、加载失败、正文为空各有明确状态；不得用伪造内容替代失败结果。赛前开发模式可以使用仓库内原创演示材料和预设回答，但页面、来源脚注与导出卡必须明确标注“开发演示、非知乎正式内容”，且该模式不得调用赛事内容接口或赛事模型。

### 阅读工作台

桌面端左侧为原文片段，右侧为学习区。学习区的主按钮是“AI 帮我读懂”，次入口是“我先说说理解”。移动端上下排列，来源和核心操作均可访问。

右侧结果依次展示：核心观点 → 作者公开论证步骤 → 适用条件与依据 → AI 批判性提醒 → AI 构造场景 → 一分钟理解挑战 → 建议追问 → 继续追问区 → 可按个人场景调整的行动建议。自行复述时增加理解核对和修订区域。点击引用可定位左侧对应片段，不要求用户读 API 地址或技术字段。

建议视觉方向：清爽的阅读界面，以白色或浅纸色为底、蓝色为主要操作色，用清晰的排版区分原文、AI 讲解和用户文字。正式样式尚未定稿；优先完成真实可打开的网页供用户检查。

### 学习卡

导出经过基础排版的 Word（`.docx`）；用户无需注册即可完成核心体验。内容包括来源、AI 讲解或用户复述、引用、可选修订记录、理解挑战问答与核对、继续追问记录、用户场景、行动建议、完成标志和可选回顾时间。

用户未提供具体情境时，AI 给出可调整的示例，不假定用户的课表、能力或健康状态。不得将生成的日期与安排描述为用户已承诺。

## 5. 功能需求与验收标准

| 编号 | 要求 | 验收标准 |
|---|---|---|
| F01 | 获取知识列表与详情 | 只读取实际列表中的字符串 work_id；展示标题、作者和可读范围；失败可手动重试 |
| F02 | 直接用 AI | 不填写任何复述即可生成讲解和行动建议，并可直接导出 |
| F03 | 自行复述 | 能提交自己的文字并收到带来源的核对，原始文字不被覆盖 |
| F04 | 引用可核对 | 引用确实存在于当前获取的正文中，点击可查看对应位置；不匹配的引用不能呈现为已验证依据 |
| F05 | 清楚标识来源 | 原文、AI 生成、用户输入/编辑可区分；未参与复述时不伪造“我的理解” |
| F06 | 行动可修改 | 显示一个行动建议及完成标志，允许编辑；默认标为待尝试 |
| F07 | 学习卡导出 | Word 文档包含来源与生成方式，中文正常、分节清晰并可直接分享或打印；AI 路径不强制追加手写或确认步骤 |
| F08 | 路径与文章切换 | 切换路径保留当前输入；切换文章不混入旧引用或过期请求返回的结果 |
| F09 | 生成与失败状态 | 生成中防止重复提交；服务端要求同源 Origin、按来源限频并设置累计请求预算闸门；超时、限额、网络或解析失败可恢复，不显示虚构成功，不清空用户文字 |
| F10 | 公网完整体验 | 评委能从选内容走到导出；桌面和手机均可用；具体部署平台另行决定 |
| F11 | 深度讲解与继续追问 | 展示作者公开论证步骤、边界与具体场景；用户可追问，每条回答都关联当前文章中可逐字定位的引用 |
| F12 | 赛前开发演示 | 正式列表为空时能说明赛事内容可能尚未开放；独立 demo 命令可离线跑通全流程，且全程不冒充正式内容或真实模型 |
| F13 | 两类证据标签 | 页面只出现“原文理解”和“AI 延伸”；原文类陈述保留可定位引用，AI 类内容不冒充作者原话 |
| F14 | 一分钟理解挑战 | 每份讲解给 1 个可由当前片段回答的问题；回答后给带引用核对；仅遗漏时显示 1 个变式题，不评分、不宣称掌握 |
| F15 | 按个人场景调整行动 | 用户可输入一句场景并得到新的行动、完成标志和回顾安排；结果仍可编辑并标为 AI 延伸、待尝试 |

## 6. AI 与内容约束

- 知乎知识列表/详情是材料来源，应用生成模型需要单独接入。开发用模型连接成功不能代替产品运行时集成。
- 生成只使用当前选择的已获取片段。产品应提示“基于当前可读片段”，不能暗示获取了全文或搜索了全部知乎。
- 9 月 9 日的历史样本为列表 10 项，抽查两篇正文各 3000 字符且疑似截断；这些不是当前接口规模承诺。
- 生成观点与引用需有稳定对应关系；对引用原文做本地匹配检查。匹配成功只能证明引文存在，不能单独证明结论正确。
- 作者观点保留“作者认为”等归属，不能自动升格为普遍事实或专业诊断。
- 外部正文视为内容材料，不能执行其中的指令或据此调用工具。
- 只有用户主动点击生成、核对或重新生成时调用模型；不因普通页面切换反复消耗额度。模型、预算与请求参数待实现时确定。
- 凭证仅在后端保存，不进入浏览器、学习卡、日志或 Git。原文及用户输入默认不发送到额外统计服务。

## 7. 首版范围和暂不纳入项

首版已采用 Node 24 与原生浏览器模块实现两种入口、两类证据标签、引用核对、一分钟理解挑战、场景化行动、Word 学习卡导出和失败恢复。公网体验及部署平台仍待开赛后完成。

首版暂不加入长期打卡、复杂知识图谱、教材上传、语音、多人协作学习或全站搜索。知乎 OAuth 依据后续需求决定，不作为当前首版体验的前置条件。
