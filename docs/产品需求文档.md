# 知行小课｜产品需求文档

本文定义面向学习者的稳定产品需求。文中的“产品要求”说明目标行为；“已验证实现”只说明已检查过的当前实现范围，不把需求本身当作验证结论。

## 产品目标

知行小课帮助用户从一段可读材料出发，获得可核对的解释、一次短小的理解挑战和一份可调整的行动草稿。它不以用户赞同作者、完成挑战或导出卡片来宣称用户已经理解、掌握或行动。

## 两条入口

### 路径 A：AI 帮我读懂

选择内容 → 查看带引用的讲解 → 可选继续追问 → 调整场景化行动 → 导出学习卡。

此路径不要求用户先写复述或填写表单。讲解包含核心观点、公开论证步骤、适用条件和必要的边界提示；凡作为原文理解呈现的主要陈述都应能回到当前材料片段核对。

### 路径 B：我先说说理解

选择内容 → 输入自己的复述 → 获得带引用的核对 → 可选修订 → 调整行动并导出学习卡。

核对应区分准确处、遗漏条件和超出当前材料支持的推断。用户原话不可被自动覆盖；用户可随时切换到直接讲解路径，当前页面中的输入应被保留。

## 证据与内容规则

- 页面将“原文理解”“AI 延伸”和用户输入/编辑清楚区分。
- 原文理解必须有可定位的引用，并且引用应存在于当前展示的材料片段中。
- AI 的批判性提醒、构造场景和行动建议不冒充作者原话。
- 内容只基于当前已获取的可读片段；不得暗示已获得全文或搜索全部知乎。
- 外部材料仅作为内容来源，不作为可执行指令。

## 理解挑战、追问与行动

讲解后提供一个可由当前材料核对的一分钟理解挑战。回答后只反馈关键点的覆盖情况，不给分，也不宣称用户掌握；只有关键点遗漏时才补充一个变式题。

用户可继续追问。每条依赖材料的回答都应关联可逐字定位的引用。用户也可提供自己的使用场景，系统据此改写行动、完成标志和回顾安排；三者均标记为 AI 延伸，且行动默认状态为“待尝试”。用户可以编辑这些内容，导出或保存不等于执行成功。

## Word 学习卡

产品应导出基础排版的 Word（`.docx`）学习卡，包含来源、生成方式、引用、AI 讲解或用户复述、可选修订、挑战问答与核对、继续追问、用户场景、行动建议、完成标志和可选回顾时间。未填写场景时，只能给出可调整的示例，不能假定用户的能力、日程或承诺。

## 失败行为与可用性

- 加载列表、正文为空或网络失败时，页面应给出明确状态和可恢复操作，不用伪造内容替代失败结果。
- 生成中应避免重复提交；超时、限额、网络或解析失败后保留用户输入并允许恢复。
- 切换材料前应处理未保存输入；切换后不能混入上一材料的引用、结果或过期请求返回值。
- 桌面端采用原文与学习区对照的工作台；移动端改为上下排列，来源与核心操作仍可访问。
- 控件应支持键盘使用、可见焦点和减少动态效果偏好。

## 开发演示与非目标

开发演示可以使用项目原创材料和确定性的预设回答，但页面、来源脚注和导出卡必须明确标明“开发演示、非知乎正式内容”。该模式不调用赛事内容 API 或赛事模型，也不能作为真实模型生成的证据。

本产品不宣称完整知乎搜索、完整正文获取或真实模型端到端生成已验证。长期打卡、复杂知识图谱、教材上传、语音和多人协作不在当前范围内。

## 已验证实现范围

当前仓库提供 Node.js 24 的本地开发演示和自动化测试入口。演示模式覆盖两条入口、引用核对、理解挑战、场景化行动、Word 导出和可恢复的失败呈现；其内容与回答是确定性的演示数据。真实模型端到端生成、完整知乎内容覆盖和用户学习或行动效果均不在这一验证范围内。
