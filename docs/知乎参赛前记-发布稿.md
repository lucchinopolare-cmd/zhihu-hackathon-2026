# AI 给我讲完一篇知乎文章，我想知道它有没有多说半句

先说背景：我在参加知乎黑客松 2026 校园新锐季，报的赛道是「知识炼金场：学习工具与知识生产」。这是一篇 2026 年 9 月 11 日写下的赛前思路和本地原型记录；9 月 13 日 10 点开幕后的当前状态以 [项目档案](../项目档案.md) 为准。

当时在做的工具叫「知行小课」；2026 年 9 月 13 日用户已确认它为正式参赛作品。想法很简单：**读懂一条知乎建议，试出自己的答案。**

你挑一篇知乎知识内容，它给你一张学习卡。卡上是这篇文章的核心观点、这个观点在什么条件下成立、有什么要留意的，以及一个今天就能试的小行动。每条结论后面挂着原文出处，点回去就能看作者到底怎么说的。

这篇先分享三件事：

1. 两个入口怎么设计，让不想打字的人也能拿到东西
2. 怎么让 AI 讲的每句话都能追回原文
3. 实测接口时撞到的一个 3000 字符，以及我为它写的那段代码

这是一篇赛前思路和本地原型记录，不把本地演示当作正式参赛作品或公网交付结果。开幕后是否复用、怎样复用，仍以主办方规则为准。

---

## 一、两个入口，不逼你打字

我自己用 AI 读文章的时候，经常是这样：一键总结出来了，读着很顺，然后就翻页了，第二天什么也不剩。但如果一个工具非要我先答题、先复述才给我反馈，我大概第一次就关掉了。

所以我做了两条并行入口，共用同一套卡片输出：

|  | 路径 A：直接用 AI | 路径 B：自己先复述 |
|---|---|---|
| 入口 | 「AI 帮我读懂」（主按钮） | 「我先说说理解」（次入口） |
| 前置 | 无，不用填任何东西 | 输入自己的复述 |
| AI 产出 | 带引用的讲解 + 行动草稿 | 区分三类：讲对的、漏掉的条件、超出原文支持的推断 |
| 导出 | 直接可导出 | 保留原始复述和修订记录 |

路径 A 保证零门槛。路径 B 是我更喜欢的那个：**它不判你对错，而是把你的理解和原文做差分。**

最有意思的是第三类，「超出原文支持的推断」。你以为文章是这么说的，其实那半句是你自己脑补的——普通总结工具通常不会告诉你这件事，因为它根本不知道你脑子里想了什么。

最初的版本只有路径 B，必须先复述才解锁后面所有功能。后来撤掉了，一个不想打字的人在那个设计里什么都拿不到。

## 二、每句话都能追到出处

这是我最在意的一点。

AI 总结有个我一直不舒服的地方：读起来很顺，但我分不清哪句是文章原意、哪句是模型自己补的。它多说了半句，我后面的推理就可能建立在一个假前提上，而且我不会发现。

所以卡片上四类信息强制分开标注：

| 卡片内容 | 标注方式 | 能否修改 | 状态 |
|---|---|---|---|
| 原文依据 | 带引用编号和段落号，可回查 | 不可改 | 客观材料 |
| AI 讲解 | 标「AI 生成」，观点后挂引用编号 | 不可改 | 供核对 |
| AI 行动建议 | 标「AI 建议」，不冒充作者原话 | 可改 | **待尝试** |
| 用户自己的复述 | 保留原始输入和修订记录 | 可改 | 用户创作 |

配套写进验收标准的两条硬规则：

一是没参与复述的时候，界面上不出现「我的理解」「我已掌握」这类标签。点一下按钮和学会了是两件事。

二是行动建议的默认状态永远是「待尝试」，导出了也还是「待尝试」。我不想让人从一次导出里拿到「我已经在做了」的感觉。

## 三、我遇到了一个 3000 字符

赛事给的知识接口是两个无鉴权 GET，不用登录、不用 Access Secret、不用 OAuth，用户零凭证就能读取赛事接口当时返回的内容。

但 9 月 9 日实测的时候我发现一件文档里没写的事：抽查的两篇内容，`content` 字段长度**都恰好是 3000 字符，末尾句子是断的**，其中一篇停在一个「懒」字上。

我没法证明它一定是截断，也没法证明它是全文。于是代码里专门有个函数只负责报告这个状态，不下结论：

```javascript
export function contentTailSignal(content) {
  const trimmed = content.trimEnd();
  const hasTerminalPunctuation = /[。！？；…]$/u.test(trimmed);
  if (content.length === 3_000 && !hasTerminalPunctuation) {
    return 'possible';   // 疑似截断
  }
  if (!hasTerminalPunctuation) {
    return 'weak';
  }
  return 'none';
}
```

产品上的处理：所有生成结果都标「基于当前可读片段」，永远不说「已获取全文」。同赛道的朋友如果也抽查过，欢迎在评论里说一下你拿到的是多少字符，多几个样本就能判断这是不是普遍现象。

顺便说几个同类的坑。列表的 `labels` 字段不能直接当可靠分类，样本里有个标题明显是职场内容的条目，标签却是「悬疑 / 警察 / 犯罪 / 现代」。接口文档没有搜索、筛选、分页参数，所以「搜索」只做已加载列表的本地匹配，不包装成「全站检索」。接口失败或返回空数据时就显示真实状态，不用生成内容填坑。

## 一张示例卡

下面是按当前输出结构整理的一张示例卡，材料来自 9 月 9 日获取的赛事接口片段。它用来说明产品结构，不代表公网体验或赛事模型端到端验收已经通过：

> **实现大目标：依靠「小胜」和「闭合任务回路」**
>
> 来源作者：刀熊说说 ｜ 生成方式：示例整理 ｜ 内容完整性：未知（基于当前可读片段）
>
> **核心观点**：状态低迷时，先寻找能恢复能量感的小切口。[1]
>
> **适用条件**：适合难以启动、继续强迫自己只会更加疲惫的时候。[1]
>
> **需要留意**：这是一种行动起点，不能代替专业诊断或治疗。
>
> **原文依据** [1]（段落 p1）：当人状态不好的时候，人的能量感通道非常脆弱，这个时候如果你使用意志力来不断地要求自己……
>
> **AI 行动建议（待尝试）**：选一个十分钟内能结束的小任务，马上开始。完成标志是任务有明确结果，并记录完成后的感受。今晚用五分钟回看是否更容易继续下一步。

前面讲的三点在这张卡上都能看到：完整性写「未知」，观点挂着可回查的引用，行动建议不冒充作者原话，状态是「待尝试」，还多给了一句边界提示。

技术侧目前是 Node 24 的本地原型。`work_id` 按字符串处理且只接受本次列表返回过的 ID，带超时、响应体积上限、缓存与请求去重，没有重试风暴。

接下来最重要的不是继续堆功能，而是把一条路径跑真：选一篇内容，得到能逐条回查的讲解，问一个追问，改出一个自己愿意试的小行动，然后顺利导出。
